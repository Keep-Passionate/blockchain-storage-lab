## 2. 老师的模型与本项目的工程选择

老师提供的说明是业务需求参考，不是论文原文。我们从中采用四层实体、操作校验、检测报告存证、专家审核和审计记录。防控推荐、因果归因、知识图谱写回与模型更新当前不实现。

以下选择由本项目作出，应与论文主张分开理解：

1. **IPFS 保存报告原件。** 这篇泰山茶论文全文没有 IPFS；IPFS 来自前期讨论及本项目对“报告原件链下保存”要求的实现。CID 与报告原始字节的 SHA-256 分别记录。
2. **当前使用一个 Fabric Channel。** “四层”是业务关系，不等于四条链或四个 Channel。当前用不同记录类型组织状态；后续确有组织隔离需求，再比较多 Channel 或私有数据集合。
3. **批次绑定不可变地块快照。** 当前一个批次关联一个确定的快照 ID。地块资料发生变化时，新建快照，历史批次的含义保持可复核。多地块来源、拆批与合批是后续扩展。
4. **业务日志与数据投影分开。** 已提交链上记录的 MySQL 投影可重放；不合规原始输入、提交状态与事件消费进度包含链下独有信息，需要独立保存，不能笼统说整个数据库都可从链上恢复。
5. **组织身份仅演示职责分离。** Org1MSP 演示生产录入与检测，Org2MSP 演示专家与监管。这不是专家资质、检测机构资质或用户角色的完整认证系统。
6. **虚拟规则与虚拟数据明确标记。** 场景记录使用 `synthetic: true`、`schemaVersion: 1`。测试中的通过、拒绝或审核结果只说明软件分支运行情况，不代表真实农业合规判断或质量认证。
7. **真实事件收件与模拟通知分开。** 命令行场景有限时重放 Fabric 合约事件并持久化收件进度，再扫描该批次的 `FAIL` 检测与 `FLAGGED` 审计，按来源交易 ID 生成确定性预警 ID。通知状态为 `SIMULATED`，没有真实消息发送；移动端、全天候订阅、月度调度和认证系统适配器尚未实现。

- PDF 71 / 印刷 61 写 Fabric 1.0，下一页写 Fabric 1.1.4，环境描述不一致；本项目依据实际部署的 Fabric 2.5.16 验证结果记录环境。
- PDF 68 / 印刷 58 的浇水表复用了施肥字段名；设计我们的字段时按业务含义命名。
- PDF 66 / 印刷 56 的密码字段未说明哈希存储策略；该表不能直接作为认证实现。
- Radix-Merkle 和 SHT-PBFT 的说明不等于可复用的 Fabric 补丁。本仓库尚未取得相应源码与原始测试数据，也未复现论文的吞吐量或效率提升数字。
- 信息上链后的完整性与可审计性，不能自动证明录入信息真实。采集、检测、身份与人工审核仍有各自责任。
